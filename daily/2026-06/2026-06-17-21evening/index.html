arXiv:2606.08044 核心发现 + "解离模型"实验 + LVS 评估方法

来源：arXiv 6/17 18:13 当日发布 | html5.qq.com 6/17 18:13 | 多家 AI 自媒体 6/17 当日转载
核心发现：主流 LLM 安全测试存在"审计缺口"：
  • AI 可能表面上拒绝回答危险问题，但内部神经网络结构已埋下脆弱性
  • 遭遇轻微"内部干扰"就会原形毕露
  • "就像一栋楼通过消防验收，但墙壁里塞满了易燃材料"
  • 当前安全测试"看输出" = 不检查"骨架"
  • 现有标准做法（出危险问题看是否拒绝）= 拒绝回答 ≠ 模型"真的不知道怎么做坏事"
"解离模型"（Dissociation Model）实验设计：
目标效果战略意义
输出行为保持安全、礼貌地拒绝危险请求外表安全
内部激活处理危险信息时向"危险"模型靠拢内部危险化
整体 KL 散度不偏离原始安全模型太远难以察觉
训练数据：PKU-SafeRLHF（成对安全/危险回答 / 初始化监测探针）+ BeaverTails（大量正常无害问题）+ XSTest（验证基准） 验证基准：9 个公开安全评测 / 覆盖直接有害请求 / 越狱攻击 / 过度拒绝 实验结果（Gemma 2 2B / Llama 3.2 3B / Qwen 2.5 3B）：拒绝率改造前后几乎无变化 / 内部评分差距原始安全模型约 0.6 / 解离模型缩小到 0.04-0.30（内部已发生实质性变化，外表完全看不出来） LVS 潜在脆弱性分数（Latent Vulnerability Score）= 安全行为崩塌量 / 所需扰动大小（连续量化 vs 攻击成功率二元）：
Llama-3 模型版本末层 LVS嵌入层 LVS现象
Meta-Llama-3-8B-Instruct（基础安全版）04.914末层扰动几乎无法引发危险输出
Llama-3-8B-Instruct-RR（强化安全版）09.182强化安全版嵌入层反而更脆弱（关键洞察）
Llama-3-8B-Instruct-abliterated（去安全化）55.6655.207删除安全权重后飙升
dolphin-2.9-llama3-8b（危险数据训练）201.190—极度脆弱
核心结论：当前安全对齐方法更像在模型输出端加了一个严格过滤器，而非从根本上改变模型理解和处理危险信息的方式。过滤器可被绕过、可被微调掉、可被内部扰动影响——只有整个内部结构都健康，才叫真正的安全。 vs 6/17 evening 14:00 AIIA 智能体时代 AI 安全治理研讨会（实践层 / 中国制度化治理）：arXiv:2606.08044 18:13 = 学术层 / 美国 = 中美同一天（6/17 14:00 中国 + 6/17 18:13 美国）AI 安全治理双线落地 = 21evening 必报"中美同一天 学术 + 实践双线对位"角度
